Cómo trabajo

01

Entiendo el problema

Converso con quien va a usar el sistema todos los días: qué le hace perder tiempo hoy, qué datos necesita a mano.

02

Diseño la solución

Defino qué tan simple o compleja debe ser: a veces alcanza con HTML y JS, otras hace falta base de datos y backend.

03

Desarrollo

Construyo por partes, probando cada función contra casos reales antes de seguir con la siguiente.

04

Despliego

Publico en GitHub Pages o Railway según el proyecto, y dejo el sistema listo para usarse en producción.

05

Mantengo

Sigo disponible después del lanzamiento para ajustes, nuevas funciones o soporte cuando algo cambia.

Sobre mí

Me gusta desarrollar herramientas que resuelven problemas reales del día a día. La mayoría de mis proyectos nacieron de necesidades concretas en negocios donde construir un sistema propio terminó siendo más eficiente que adaptar uno genérico.

Empecé con sitios más simples — landings e institucionales — y fui subiendo la complejidad hacia paneles con datos en vivo, base de datos propia y lógica de negocio. Uso React cuando el proyecto lo pide y JavaScript vanilla cuando no hace falta más.

Gran parte de este trabajo lo hice con asistencia de IA como parte de mi flujo: la uso para acelerar la implementación, pero las decisiones de arquitectura, qué construir y cómo resolver cada caso de uso son mías.
